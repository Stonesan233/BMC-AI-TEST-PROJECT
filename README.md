# openUBMC AI 测试框架

面向 openUBMC 的智能化、高可靠性自动化测试框架。采用**轻量双 Agent 架构**，彻底分离执行与判断职责，从根源上消除「假 PASS」问题。

---

## 项目定位

本框架专为 openUBMC 测试场景设计，解决自动化测试中的核心痛点：能执行用例，但无法可靠判断结果。

**核心目标：**

- **消除假 PASS**：执行与判断完全解耦，独立严格验证
- **极简架构**：两个 Agent + 一个启动脚本
- **私有化部署**：完全内网隔离，适配华为昇腾 910C

---

## 核心理念

### 执行与判断彻底解耦

框架由三个核心组件构成：

| 组件 | 类型 | 职责 |
|------|------|------|
| 启动脚本 | Python 脚本 | 流程串联，无智能逻辑 |
| Test_Exec | Agent | 执行测试，收集证据 |
| Test_Judge | Agent | 严格验证，输出结论 |

**设计原则**：启动脚本只做串联，不做任何决策；智能逻辑全部在两个 Agent 中。

### 宁可错杀，不可放过

Judge Agent 采用**极度严格**的判断策略：

- 任何不确定 → FAIL
- 预置条件未满足 → FAIL
- 证据不完整 → FAIL
- 预期与实际不一致 → FAIL
- 用户列表已满 → FAIL

### 简单可靠的数据交接

通过共享目录中的 JSON 文件实现 Exec → Judge 数据交接。无消息队列、无数据库、无额外依赖。

### RAG 命令检索（必须功能）

由于测试用例描述往往较为模糊，本框架内置 **BMC Command RAG** 模块。
- Test_Exec Agent 在执行前会自动检索最匹配的历史命令模板
- 显著提升模糊用例的执行成功率（从约 10% 提升至 90%）
- 可通过配置开启或关闭

## 模型选型

| 角色 | 模型 |
|------|------|
| 框架开发 | GLM-5 |
| 执行 Agent | MiniMax-M2.5 |
| 判断 Agent | Qwen3-235B-A22B |

---

## 部署环境

两台昇腾 910C 服务器，通过共享目录连接：

- **执行服务器**：运行 Test_Exec
- **判断服务器**：运行 Test_Judge

---

## 核心优势

| 优势 | 说明 |
|------|------|
| 假 PASS 根除 | 独立判断 + 严格规则 + 证据驱动 |
| 极简可靠 | 三个组件，职责清晰 |
| 可追溯 | 每一步都有完整证据 |
| 私有化 | 完全内网运行 |
